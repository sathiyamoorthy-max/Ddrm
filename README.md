# Unified DRM Cyber Lab\n\nTwo controlled, local-only DRM security demonstrations in one repository:\n\n1. **HLS AES-128 lab** inspired by common M3U8 + key-URI workflows.\n2. **Widevine-style mock CDM/license lab** inspired by license-based DRM architecture.\n\n> This repository uses only synthetic media generated locally with FFmpeg. It does not contain or support real PocketFM/OTT credentials, production Widevine CDMs, WVD files, real license messages, third-party content keys, or arbitrary target URLs.\n\n## What the project demonstrates\n\n- AES-128-CBC encrypted HLS segments and an `EXT-X-KEY` playlist.\n- An intentionally vulnerable HLS key endpoint with no entitlement check.\n- MPD + PSSH-like metadata for a mock license/CDM flow.\n- A signed mock device challenge.\n- A vulnerable mock license endpoint that validates the device challenge but skips entitlement.\n- Patched HLS and mock-license endpoints that require server-side entitlements.\n- Telegram delivery of recovered synthetic audio.\n- Automated tests for crypto, entitlement and server behavior.\n\n## Architecture\n\n```text\n                         Telegram Bot\n                              |\n              +---------------+---------------+\n              |                               |\n              v                               v\n        HLS AES-128 Lab                 Mock CDM Lab\n              |                               |\n        M3U8 EXT-X-KEY                  MPD + PSSH-like data\n              |                               |\n     vulnerable / secure key          signed mock CDM challenge\n              |                               |\n        encrypted TS segments          vulnerable / secure license\n              |                               |\n         AES-CBC decrypt               wrapped synthetic content key\n              |                               |\n        FFmpeg remux                   AES-GCM decrypt\n              |                               |\n              +---------------+---------------+\n                              |\n                        Telegram audio\n```\n\n## Repository layout\n\n```text\napp/\n├── assets.py          # generates synthetic HLS + mock DRM assets\n├── config.py          # local-only target restrictions\n├── controller.py      # unified HLS/mock workflow controller\n├── hls_lab.py         # M3U8 parsing + AES-128-CBC decryption\n├── mock_cdm.py        # PSSH-like data, challenge, license unwrap\n├── server.py          # vulnerable + secure local Flask endpoints\n└── telegram_bot.py    # private Telegram demo bot\n\ntests/\n├── test_hls_lab.py\n├── test_mock_cdm.py\n└── test_server.py\n\nREPORT_TEMPLATE.md\nDockerfile\ndocker-compose.yml\nrequirements.txt\n```\n\n## Requirements\n\n- Python 3.12 recommended\n- FFmpeg\n- Telegram bot token from BotFather\n- Your Telegram numeric user ID\n\n## Install\n\n```bash\ngit clone https://github.com/sathiyamoorthy-max/Ddrm.git\ncd Ddrm\npython -m venv .venv\nsource .venv/bin/activate\npip install -r requirements.txt\n```\n\nWindows PowerShell:\n\n```powershell\n.venv\Scripts\Activate.ps1\npip install -r requirements.txt\n```\n\nInstall FFmpeg on Ubuntu/Debian:\n\n```bash\nsudo apt-get update\nsudo apt-get install -y ffmpeg\n```\n\n## Configure Telegram\n\n```bash\ncp .env.example .env\n```\n\nEdit `.env`:\n\n```env\nTELEGRAM_BOT_TOKEN=YOUR_BOTFATHER_TOKEN\nALLOWED_USER_IDS=YOUR_TELEGRAM_NUMERIC_ID\nLAB_BASE_URL=http://127.0.0.1:5000\nLAB_USER=student\nPORT=5000\n```\n\n`ALLOWED_USER_IDS` is mandatory. The bot will refuse to start as a public attack-demo bot.\n\n## Run with Python\n\nTerminal 1:\n\n```bash\npython -m app.server\n```\n\nTerminal 2:\n\n```bash\nset -a\nsource .env\nset +a\npython -m app.telegram_bot\n```\n\n## Run with Docker Compose\n\nAfter creating `.env`:\n\n```bash\ndocker compose up --build\n```\n\nThe Flask lab service is exposed only on:\n\n```text\n127.0.0.1:5000\n```\n\n## Telegram commands\n\n### `/hlsdemo`\n\nRuns the intentionally vulnerable local HLS flow:\n\n```text\nM3U8\n -> EXT-X-KEY\n -> unprotected local key endpoint\n -> encrypted TS segments\n -> AES-128-CBC decrypt\n -> FFmpeg remux\n -> Telegram M4A\n```\n\n### `/cdmdemo`\n\nRuns the intentionally vulnerable mock-CDM flow:\n\n```text\nMPD\n -> PSSH-like metadata\n -> signed mock CDM challenge\n -> vulnerable license endpoint\n -> wrapped synthetic content key\n -> key unwrap\n -> synthetic media decrypt\n -> Telegram MP3\n```\n\nThe vulnerable license endpoint intentionally omits the entitlement check.\n\n### `/securecheck`\n\nUses the zero-credit `attacker` identity against both secure paths. Expected result: both flows are blocked with `402 payment_required`.\n\n### `/legitdemo`\n\nUses the `student` user's two lab credits to buy:\n\n- `hls-paid`\n- `mock-paid`\n\nThen both secure flows play successfully.\n\n### `/compare`\n\nPrints a concise comparison of HLS key-URI security and license/CDM-style security.\n\n### `/reset`\n\nRestores the lab to two student credits and no entitlements.\n\n### `/health`\n\nChecks the local Flask server.\n\n## Run tests\n\n```bash\npytest -q\n```\n\nTests cover:\n\n- generated AES-128 HLS playlist and segment decryption;\n- mock PSSH/challenge/license/key-unwrapping round trip;\n- challenge tampering rejection;\n- vulnerable HLS key exposure;\n- secure HLS entitlement enforcement;\n- vulnerable mock license behavior;\n- secure mock license entitlement enforcement.\n\nGitHub Actions runs the same suite.\n\n## CLI controller\n\nWith the lab server running:\n\n```bash\npython -m app.controller hls --output recovered.m4a\npython -m app.controller mock --output recovered.mp3\n```\n\nSecure modes require a server-side entitlement first:\n\n```bash\npython -m app.controller secure-hls --user student --output secure.m4a\npython -m app.controller secure-mock --user student --output secure.mp3\n```\n\n## HOD demo sequence\n\n1. Run `/securecheck` and show that the patched design rejects the attacker.\n2. Run `/hlsdemo` and explain how missing key-endpoint authorization defeats otherwise-correct AES encryption.\n3. Run `/cdmdemo` and explain how a license server that authenticates a device but forgets entitlement can still issue content keys.\n4. Run `/reset`.\n5. Run `/legitdemo` and show correct server-side purchase -> entitlement -> playback.\n6. Show `pytest -q` and GitHub Actions.\n7. Use `REPORT_TEMPLATE.md` for the final write-up.\n\n## Important distinction\n\nThe second flow is **Widevine-style**, not Widevine.\n\nIt intentionally does not implement:\n\n- real Google Widevine protocols;\n- WVD device files;\n- CDM credential dumping;\n- real PSSH/license requests;\n- CENC/mp4decrypt against third-party media;\n- production DRM bypass.\n\nIt models the architecture safely with a synthetic challenge, wrapped key and locally generated encrypted MP3.\n\n## Security boundary\n\n`LAB_BASE_URL` accepts only:\n\n- `localhost`\n- `127.0.0.1`\n- `::1`\n- Docker service `lab-server`\n\nThere is no bot command for arbitrary URLs, cookies, access tokens, PSSH values, license URLs, WVD/CDM files or external content keys.\n\n## Report\n\nSee [`REPORT_TEMPLATE.md`](REPORT_TEMPLATE.md) for objectives, architecture, vulnerabilities, mitigation, experiment procedure, evidence checklist and conclusion.
