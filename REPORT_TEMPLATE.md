# Unified DRM Cyber Lab — College Project Report Template\n\n## 1. Title\n\n**Unified Demonstration of HLS AES-128 Key Exposure and License-Based Entitlement Failures in a Controlled DRM Cybersecurity Lab**\n\n## 2. Objective\n\nBuild a controlled local environment that demonstrates two protected-media architectures:\n\n1. HLS AES-128 encrypted media with a key URI.\n2. A Widevine-style educational model using MPD/PSSH-like metadata, a mock CDM challenge, a license endpoint, a wrapped content key, and encrypted media.\n\nThe lab compares insecure implementations with server-side entitlement enforcement.\n\n## 3. Scope\n\nAll media is generated locally with FFmpeg. The project does not use real PocketFM/OTT credentials, real Widevine device files, production license servers, or third-party content keys.\n\n## 4. Architecture\n\n### Flow A — HLS AES-128\n\n```text\nSynthetic sine audio\n    -> FFmpeg HLS segmentation\n    -> AES-128-CBC encrypted TS segments\n    -> M3U8 EXT-X-KEY\n    -> vulnerable key endpoint\n    -> local decryptor\n    -> FFmpeg remux\n    -> Telegram audio\n```\n\n### Flow B — Mock CDM / License\n\n```text\nSynthetic MP3\n    -> AES-GCM encrypted payload\n    -> MPD + PSSH-like metadata\n    -> mock CDM challenge\n    -> vulnerable or secure license endpoint\n    -> wrapped content key\n    -> mock CDM unwrap\n    -> decrypt\n    -> Telegram audio\n```\n\n## 5. Vulnerabilities Demonstrated\n\n### 5.1 Missing entitlement check on HLS key endpoint\n\nThe intentionally vulnerable `/hls/key` endpoint returns the AES key without confirming that the user purchased the content.\n\nImpact in the lab: encrypted media can be recovered.\n\nMitigation: authorize every key request and use short-lived scoped playback credentials.\n\n### 5.2 Missing entitlement check on license endpoint\n\nThe intentionally vulnerable `/mockdrm/vuln-license` validates the mock device challenge but skips the account entitlement check.\n\nImpact in the lab: a valid synthetic lab device can receive a wrapped content key without purchase.\n\nMitigation: license issuance must validate account, entitlement, content, session, and policy.\n\n## 6. Secure Design\n\nThe secure paths:\n\n- `/hls/secure-key`\n- `/mockdrm/license`\n\nrequire a server-side entitlement created through `/pay`.\n\nThe client cannot create entitlement by changing a local flag.\n\n## 7. Experimental Procedure\n\n1. Start the lab server.\n2. Start the Telegram bot.\n3. Run `/securecheck`.\n4. Confirm that the attacker identity is rejected.\n5. Run `/hlsdemo`.\n6. Observe recovery of the synthetic HLS sample through the intentionally exposed local key.\n7. Run `/cdmdemo`.\n8. Observe recovery of the synthetic mock-CDM sample through the intentionally under-authorized local license endpoint.\n9. Run `/reset`.\n10. Run `/legitdemo`.\n11. Compare secure server-side entitlement playback with the vulnerable flows.\n12. Run `pytest -q` and include the test results in the report.\n\n## 8. Evidence to Capture\n\n- Telegram screenshots of `/hlsdemo`, `/cdmdemo`, `/securecheck`, and `/legitdemo`.\n- Terminal screenshot of `pytest -q`.\n- Architecture diagram.\n- M3U8 excerpt showing `EXT-X-KEY`.\n- Mock MPD excerpt showing the PSSH-like field.\n- HTTP status `402 payment_required` from secure paths.\n\n## 9. Limitations\n\nThis project is a protocol-learning lab, not a production DRM implementation.\n\nThe mock CDM flow is intentionally not compatible with Widevine. It does not use a WVD file, real CDM private credentials, real Widevine license messages, or CENC decryption.\n\n## 10. Conclusion\n\nThe experiment demonstrates that encryption alone does not provide authorization. Protected-media security depends on correct entitlement enforcement, key/license access control, short-lived credentials, and server-side policy checks.
